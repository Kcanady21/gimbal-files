# P2m2: delayed folder-size totals in hover details

Tags: **[observed]** this working tree, tests and smoke log; **[read]** pinned crate/GTK source or command output; **[inferred]** behaviour that still needs Kyle's live display/interaction.

## What was built

**[observed] Delayed, in-place folder totals.** The main grid and every split tile use the same `FolderView` cell adapter. A cell now owns a `query-tooltip` handler instead of a static `set_tooltip_text`: the handler returns the existing plain-text name/type/modified details for every entry and, for a folder, resolves the current cell binding rather than a pointer coordinate. A separate `EventControllerMotion` starts a 500 ms continuous-hover timer; only that timer (or a keyboard/assistive `query-tooltip` with `keyboard_mode`) calls the folder-size service. Binding, listing, sorting, selection and ordinary motion never start a recursive walk. Progress and completion call `GtkWidget::trigger_tooltip_query` on the same cell, so a visible tooltip is requery-updated in place without leave/re-enter.

**[observed] Tooltip states.** `folder/size.rs` keeps one `TooltipModel` per active cell and renders plain text:

- initial: the accepted `name / Type: Folder / Size: Folder / Modified: ...`;
- running: `Size: Calculating…` plus a throttled `Found N files, M folders`;
- finished: `Contents: 12.4 MiB`, `On disk: 12.6 MiB`, `Contains: 27 files, 3 folders`, `Calculated: 12 s ago`;
- cached: the same result immediately with `(Cached)`;
- stale: `Size: Last calculation (stale, updating…)` while a new scan replaces it;
- partial: `At least … (partial)` on both byte lines, `(at least)` on the counts and `Partial: permission denied / scan limit / depth limit / time limit`;
- remote: `Size: Not calculated for remote folders`;
- symlink root: `Size: Not calculated (symlink target was not scanned)`;
- missing/unavailable: `Size unavailable`.

Hard-link de-duplication, skipped mounted filesystems and repeated-directory aliases get one line only when they occur. The same text is written to the cell's and label's accessible description as it changes.

**[observed] Core walk.** `fm-core/src/folder_size/` contains the GTK-free contract, native walker, cache and tests. It is iterative, uses `symlink_metadata` only, includes hidden entries, includes directory metadata including the root, and never opens file contents, special files or symlink targets.

- Contents = sum of regular-file `st_size`.
- On disk = allocated `st_blocks × 512` for regular files, directories (including root) and symlinks.
- Identity de-duplication is by `(device, inode)`; duplicate directory entries increment `hard_links_deduplicated` and contribute no second data/blocks, while entry counts still describe every directory entry.
- Symlinks contribute only their own allocated blocks; their targets are not walked.
- FIFOs, sockets and device nodes are counted as entries but contribute no data or blocks and are never opened.
- The walk starts on the root's device; child directories on another device are counted as `mounts_skipped` and not descended. Visited directory `(device, inode)` pairs prevent cycles/aliases. Same-device bind-mount boundaries are not specially detected; the actual rule is device/inode based.
- Cancellation and the budget are checked between entries and before opening the next directory. `read_dir` is streamed one entry at a time, so a huge directory is not materialised first and a cancelled reader is dropped promptly. A blocked native `lstat`/`read_dir` cannot be forcibly interrupted; the worker waits for that call to return. No thread is killed.

**[observed] Bounds and defaults.** `MAX_ACTIVE_SCANS = 2` process-wide worker threads; `MAX_PENDING_DEMANDS = 8`; `MAX_VISITED_ENTRIES = 100_000`; `MAX_DEPTH = 128`; `DEFAULT_BUDGET_MS = 5_000`; progress no more often than 250 ms (four per second); `CACHE_ROOTS = 256`; `CACHE_TTL_MS = 30_000`. Every limit produces an explicit partial result rather than a complete-looking total. The service keeps one demand per `FolderView`; a new hover, leave, navigation, unbind, Refresh, window close or superseding demand cancels the old token.

**[observed] Cache and invalidation.** `FolderSizeCache` keys by absolute root path, device/inode, listing modified time (`sec` + GIO `modified-usec × 1000`) and `POLICY_VERSION`. Fresh hits are returned synchronously and labelled `(Cached)`. Expired entries provide the optional stale display while a new scan runs. `nav.refresh` invalidates the displayed root; a finished file operation invalidates all known roots conservatively. A remote refusal is not cached as a local total. The TTL is the fallback for descendant changes the view did not see; no recursive watcher is created.

**[observed] Binding safety.** Each cell binding stores the exact root identity, name, `FileRevision` and details. A result is accepted only when its token, current `ListItem` binding, root, name and revision still match. A recycled A→B cell rejects late A results, including same basenames under different roots. `unbind` cancels the cell's hover/active token. `FolderView::drop` cancels its remaining token; `app.quit` calls the service's shutdown, which cancels queued/running work and joins both workers.

## Totals, partial and cache semantics

- **[read]** "Contents" is filesystem-reported regular-file length, not an exclusive logical measure; compression, extents and shared blocks are not reconstructed.
- **[read]** "On disk" is reported allocation (`st_blocks × 512`), not `st_size`, and includes directory/symlink metadata.
- **[read]** A partial result is always rendered with `At least`. Reasons are the first-class `PartialReason` values from permission denial, entry/depth/time limits, disappearing/unreadable entries and overflow.
- **[read]** Hard-link de-duplication and mounted-filesystem exclusions are disclosed only when their counters are non-zero. Cross-device totals are not promised.
- **[read]** Cache entries retain complete and partial state separately. A root identity/revision/policy mismatch is a miss; no result is installed for a cancelled scan.
