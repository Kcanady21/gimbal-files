## What I built

- `crates/fm-ui/src/trash.rs`: `TrashBrowser` is now an expanding central page,
  not an `adw::Dialog`. It keeps the title, Back to Files, Restore, Empty Trash,
  Refresh, the virtualised `ListView`/`MultiSelection`, metadata rows, status,
  progress and Cancel. The dialog shell and its content-width multiplier are
  gone. The page is installed as the `"trash"` child of `Content`'s existing
  `gtk::Stack`.
- `crates/fm-ui/src/content.rs`: `Content` owns the transient Trash page state,
  adds the page once, switches the stack without unparenting the folder or split
  page, hides the folder status chrome while Trash is visible, and ignores model
  refreshes caused by jobs or monitors while Trash is visible. `listed_names`
  returns nothing in that state, so a hidden selection cannot leak into a
  command.
- `crates/fm-ui/src/frame.rs`: the window still owns at most one
  `Rc<TrashBrowser>`. Repeated `trash.open` uses `OpenAction::ShowExisting`.
  `leave_trash` returns to the unchanged page, updates the header, and has the
  browser cancel only the confirmation job it owns. Every browser command
  callback now uses a weak browser reference; the page and monitor therefore do
  not form an `Rc` cycle.
- `crates/fm-ui/src/header.rs`: while Trash is visible the path bar says
  “Trash”, the path entry is not editable/focusable, Up and Forward are
  insensitive, and Back is labelled “Back to Files” and stays available.
  Escape returns from Trash through the same `nav.back` path. Ordinary path and
  button state is rebuilt on exit.
- `crates/fm-ui/src/app.rs`: commands are routed to the visible page before the
  hidden folder context is filled. Ctrl+A/selection.none use the Trash list;
  `nav.back` returns without calling the model's history; `nav.refresh` refreshes
  Trash; `nav.go`, pill/group focus and sidebar destinations leave Trash first.
  File open, trash, cut/copy, paste, rename, new-folder, search, disk usage and
  Up/Forward/path focus are refused with a visible status. Delete in Trash says
  exactly “Items are already in Trash”. Restore and the established global Undo
  remain available, and Undo reports its summary in the page.
- `crates/fm-ui/src/fileops/mod.rs`: `FileOps::cancel_job(id)` cancels only the
  job whose id still matches the current job. A page leaving while its Empty
  Trash confirmation is pending calls this, not the process-wide
  `cancel_current`, so another window's job is untouched.
- `docs/notes/P2k2-r2.md`: this file.

No core, registry, dependency, manifest, lockfile, spike or runner file was
changed. **[observed]**

## Ownership and lifecycle

The window owns one `TrashBrowser` in `WindowUi::trash`. The browser owns its
widgets, list model, selection, listing thread handle, poll timeout, refresh
timeout and `GFileMonitor`. `Content` owns the stack child, so the page remains
parented while hidden and the ordinary folder/split widgets are never rebuilt
by opening or closing Trash. Signal closures that can outlive a click use
`Weak<TrashBrowser>`; the only strong cycle would have been browser -> widget ->
closure -> browser, and that is removed. **[read/observed]**

The Empty Trash confirmation stores `pending_job: Option<u64>` and the one
`adw::AlertDialog`. A response is accepted only when its id equals
`pending_job` (`confirmation_action`); a response or close for another id is
ignored. Leaving the page, closing the window or replacing the page takes the
pending id and dialog, calls `FileOps::cancel_job(id)`, and closes the dialog.
The P2k `closed`-before-`response` idle check is retained, and a close with no
answer becomes Cancel for that scoped job only. The plan snapshot, revalidation
and permanent-delete refusal in `fm-core` are unchanged. **[read/observed]**

A confirmation that arrives after the page has already been hidden is refused
at `Process::fileop_empty_confirmation`: it checks `trash_visible()` and calls
`cancel_job(id)` instead of showing a dialog for a vanishing page. Job events and
monitor refreshes update the browser's own labels and controls; they never focus
a file view. **[read/inferred]**

## Navigation and visible-page routing

`route_on_trash_page` is the one pure routing table used by
`Process::handle_command`. Its important cases are:

- `selection.all` / `selection.none`: operate on `MultiSelection` in the Trash
  page, never on the model's hidden folder selection.
- `nav.back`: `BackToFiles`; `back_consumes_history(true)` is false, so the
  folder's back stack is not changed. Once files are visible the same function
  returns true and ordinary `nav.back` resumes.
- `nav.go`, `tab.new`, `tab.focus`, `group.split`, `group.add-tab`: leave Trash
  explicitly, then run the requested destination through the existing model.
- `nav.refresh`: reload the visible Trash listing.
- `nav.up`, `nav.forward`, `nav.focus-path`, `file.open`, `file.trash`,
  `file.cut`, `file.copy-to-clipboard`, `file.copy`, `file.move`, `file.paste`,
  `file.rename`, `file.new-folder`, search and disk usage: refuse with a status.
- `trash.restore`, `trash.empty`, `trash.open` and `file.undo`: pass through to
  their existing handlers.

Model events caused by a job or `GFileMonitor` reach `Content::show` with
`RefreshCause::Background`; `keeps_trash_page(true, Background)` is true, so the
page stays visible. Only explicit navigation calls `leave_trash` with
`RefreshCause::Navigation`. The normal page is not rebuilt or focus-stolen.
**[read/observed]**

## Empty Trash remains incomplete

The production limitation is unchanged from P2k2-r1: the installed
`gvfsd-trash` does not advertise `etag::value`, so the production identity has no
verified object/revision token and `execute_empty` refuses each item with
“Cannot verify this Trash item is unchanged”. The workspace page can show the
confirmation, the immutable snapshot and the per-item refusal, but **refusal is
not successful emptying**. The production Empty Trash backend still needs
verified revision support or another backend-safe compare-and-delete design.
No deletion restriction was removed for this presentation change. **[read/observed]**
