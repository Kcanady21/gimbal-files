# P2g: the look module and the window frame

## What I built

- `crates/fm-ui/src/look/`: one shared look module.
  - `tokens.rs`: one merged design-token table and one colour-role table.
  - `css.rs`: one merged `css(scale, font, opacity)` for every `gl-` class the
    header and body prototypes styled, plus the ported header-fit and
    pill-drag arithmetic and both prototype style test suites.
  - `theme.rs`: the P1f Noctalia watcher. The watcher owns its
    `gio::FileMonitor`s and its debounce `SourceId`; dropping the look drops
    them instead of leaking them.
  - `blur.rs`: the `ext-background-effect-v1` request, its rounded-region
    builder, and live opacity/scale updates.
  - `motion.rs`: `SLOWDOWN = 1.5` and `ms(base)`.
  - `icons.rs`: the six mockup SVGs embedded with `include_bytes!`, one shared
    `gtk::Svg` per icon, `gtk::Image::from_paintable`, and the
    `FOLDER_PALETTE`, `SAVE_AS_PALETTE` and `FLOAT_PALETTE` strings. No icon is
    loaded through the icon theme.
- `crates/fm-ui/icons/`: `close.svg`, `float.svg`,
  `gimbal-discard-symbolic.svg`, `gimbal-folder-symbolic.svg`,
  `gimbal-save-as-symbolic.svg`, `gimbal-save-symbolic.svg`, copied unchanged
  from the spike.
- `crates/fm-ui/src/layout.rs`: the width split, the insets and positions, the
  strip width, the button glide, `motion_width`, `collapse_progress`,
  `outline_opacity`, `one_column_width` and their tests.
- `crates/fm-ui/src/frame.rs`: the empty window frame and the r9 sidebar
  animation.
- `crates/fm-ui/src/commands.rs`: the pure hotkey-to-invocation mapping and the
  UI handler that carries its caller.
- `crates/fm-ui/src/log.rs` and `main.rs`: the `GIMBAL_LOG=1` line format,
  config loading, one `ConfigFile`, app startup and lifetime.
- `Cargo.toml` / `crates/fm-ui/Cargo.toml`: the three spike pins.
- `Cargo.lock`: regenerated by Cargo.
- `deny.toml`: the two `gdk4-wayland` ban entries and the `ISC` license.
- `docs/notes/P2g.md`: this file.

### One token table and one stylesheet

The two spike token tables are now one table in `look/tokens.rs`. Every name
the two tables shared has the same value; the test
`tokens_lost_nothing_in_the_merge` pins the shared values and checks that each
table's own extras survived. All tokens either program used are present. `[observed]`

The two stylesheet generators are now `look::css::css(scale, font, opacity)`.
It contains every `gl-` class either program styled. The rules are one per line,
which is the header test's shape, and the body's multi-rule lines were split
accordingly. `[observed]`

Where both programs generated a rule for the same selector, I kept one:

- `window.gimbal-look` — identical in both; one rule.
- `.gl-icon-button` base — kept the body's rule: `gap-s` padding, 32 px icon,
  `radius` (12) corners, a 48 × 48 button. That is the button whose footprint
  r9's 67 px strip and its 48 px slot rely on. The header's differing values
  are now modifiers: `.nav` gets `min-width: icon-nav`, `min-height:
  control-h`, `radius-icon` and the horizontal-only padding; `.searchbtn`,
  `.winbtn`, `.float` and `.close` keep the header's sizes. `[observed]`
- `.gl-frame` — kept the body's behaviour, i.e. no rule. The header's old
  `line-heavy` border was already superseded by the Nov 1 spec ("the window
  frame is gone") and would have added a border and margins the body geometry
  does not account for. The class remains on the frame container for the
  transparency descendant selector. `[observed]`
- `.gl-pill` — merged the body's height, padding, border and fill with the
  header's `background-color` transition and its `.tab` / `.group` 270 px
  minimum. The body's `.gl-pill.tab.wide` set the same 270 px, so it was
  dropped in favour of the header selector. `[observed]`
- `.gl-pill label`, `.gl-pill-close`, `.gl-pill-close:hover`,
  `.gl-pill-close:focus-visible`, `.gl-pill.active`, `.gl-pill.selected` and
  `.gl-pill.active.selected` were identical or compatible; one each.
- `.gl-title` — merged the body's `text-title` size with the header's
  `window_fg_color`.
- `.gl-header-slot` and `.gl-header` are both kept: the empty strip uses
  `.gl-header`; `.gl-header-slot` remains for the old body harness and later
  widgets.

`[observed]`

Two test adaptations, both deliberate:

- The body's `nov_1_outlines_and_contrast` test asserted that no
  `alpha(@accent_color` appeared anywhere. That was a proxy for "the focus
  ring is not translucent". The merged header needs
  `alpha(@accent_color, 0.35)` for text selection, so the test now checks that
  the focus ring itself is `0 0 0 2px @accent_color` and is not an alpha. The
  focus ring and selection values are unchanged. `[observed]`
- The spike's stylesheet clamped opacity to `0.50..1.00`. The config permits
  `0.00..1.00`, so the merged stylesheet clamps to `0.00..1.00` and the test
  checks `0.20`, `0.00` and an over-range `1.50`. This is the brief's
  "don't clamp it differently from the config". `[observed]`

### Settings from the config

Startup loads `ConfigFile::load(default_config_path())` once. Every
`ConfigProblem` is printed through `GIMBAL_LOG=1`; there is no problems UI yet.
The one `ConfigFile` lives in `App` for the process, so the typed config and
the `toml_edit` document stay in step. `[observed]`

The look reads:

- `scale = look.base × look.scale`;
- `opacity = look.opacity`;
- `font = look.font`, with an empty string meaning "the desktop's font" (no
  `font-family` rule);
- both sidebars' `width` (design px) and `collapsed` state.

The spike's `DEFAULT_OPACITY` is no longer a look token: the default (0.85) lives
once in `fm_core::config::DEFAULT_OPACITY`, so the look cannot drift from the
config default. `[observed]`

`[observed]`

A very low opacity is not clamped to the spike's old 0.50. At `0.00` the
window background and every translucent fill disappear completely; text,
icons, outlines, rules and the focus ring stay solid, and the blur region is
still requested because the value is below 1.00. That is the config's choice,
not a fallback. At `1.00` the blur region is removed and the window is opaque.
`[inferred]` (the CSS/blur path is observed; the fully transparent visual is
not).

### Theme, blur and motion

The Noctalia watcher is the P1f one: it adds a USER-priority provider, watches
`~/.config/gtk-4.0/noctalia.css` and its one-level `@import`s, and reloads the
main file 200 ms after a change. The watcher struct owns the monitors and the
pending source. `[observed]`

The blur module binds `ext-background-effect-v1` on GDK's own `wl_display`,
checks the blur capability, builds a rounded region that excludes GTK's
client-side shadow, and flushes/queues a frame after each change. Opacity 1.00
removes the region; below 1.00 restores it. Scale changes update the region's
corner radius. `[observed]`

`motion::ms` multiplies every duration by `SLOWDOWN = 1.5`; the sidebar
animation uses `ms(200)` (300 ms) and the pill transition uses `ms(120)` /
`ms(150)`. No widget writes a raw duration. `[observed]`

### Frame

The window is an `adw::ApplicationWindow` with `fm_core::APP_ID`. It contains:

- an empty `gl-header` strip, `header-h` tall;
- a `gl-frame` body with two nested horizontal `gtk::Paned`s:
  left sidebar | (content | preview);
- two separate `gl-panel` sidebars, each with its title row ("Pinned Folders",
  "File Name"), a rule and a collapse button;
- a content area holding only the status line "Files: 0, Folders: 0", with the
  inset `gl-rule` above it.

Each sidebar lives in an overlay whose main child is an `EXTERNAL` horizontal
`ScrolledWindow`: the paned moves a clipping viewport, so the panel keeps its
layout and is cut at the moving edge instead of being squeezed. A separate
`gl-panel-outline` follows the edge and fades over the last 35 %; the button is
an overlay child and glides on its margin. The outline and button are not
clipped. A second click reverses from the current width, a resize/scale change
retargets, and the saved width is never touched by an animation. `[observed]`
(the arithmetic and timer widths); the visual is for Claude.

Panel placement is the Nov 1 one: `gap-s` in from the window's outer and bottom
edges, directly under the header, with the collapsed strip keeping the same
insets. `[observed]`

### Commands and hotkeys

`commands::bindings` is a pure `BTreeMap<String, Hotkey> -> Vec<(String,
Invocation)>` function with a test. `install_hotkeys` binds every entry in one
window-level `gtk::ShortcutController` (global scope). An accelerator that
`gtk::accelerator_parse` rejects is logged as
`hotkey: cannot parse accelerator …; skipped`; the others still install.
`[observed]`

A hotkey's `CallbackAction` builds its invocation and calls
`Registry::dispatch(Caller::Hotkey, …)` with a `UiHandler` holding the caller.
The handler is a `Weak<App>` plus `Caller`, so it knows its caller without
changing `fm-core`'s `Handler` trait. The handler:

- for every `Settings` command, calls `config::change_for` with the home folder
  as the current folder, applies the resulting `Change` through the one
  `ConfigFile`, then updates the look:
  - `SetScale` regenerates the CSS, resizes the Rust-side width requests and
    margins, updates the blur scale and re-splits the body;
  - `SetOpacity` regenerates the CSS and updates/removes the blur region;
  - `SetSidebarCollapsed` starts the r9 animation;
- for every other command logs `command: <name> not built yet`.

The collapse buttons dispatch `view.toggle-sidebar side=left|right` as
`Caller::Ui`, so a button and a hotkey run the same command. A border drag
updates the in-memory width each frame but writes `Change::SetSidebarWidth`
only when the button is released (a capture-phase legacy event controller),
not on every `position` notify. `[observed]`

The `ConfigFile` borrow is never held while calling code that can re-enter it:
the apply result is bound before matching, because a `match` scrutinee borrow
would live through the whole match. The timer caught this as a panic during
development; the delivered code has the fixed form. `[observed]`
